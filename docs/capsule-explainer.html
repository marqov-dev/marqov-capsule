Marqov Capsule

A capsule is a sealed, portable record of a quantum experiment. It holds what ran, where it ran and what came back, and it is named by a hash of its contents.

mqc:1:65c5c776ab13f3385f6ea8c00b08d5921b75c9253d3d4cd2a354f6d73a0b0228

Quantum results are hard to check after the fact: files drift, notebooks change and the run details get lost. A capsule fixes the record at one moment, so anyone holding its ID can tell whether they have those exact bytes. The format is an open specification (CC-BY-4.0), and the Python tooling is open source under Apache 2.0 on GitHub.

What is inside

A capsule is a directory of ordinary files. pack turns it into one .capsule file, a gzipped tar that comes out byte-identical every time.

How tampering shows up

Each layer pins the one before it. Change a payload byte and layer 1 fails. Regenerate .checksums to hide that and layer 2 fails. Rewrite the manifest too and you get a valid capsule with a different ID, which layer 3 catches against the ID you trust.

So a pass means the bytes have not changed since the ID was produced. It does not prove the science is right, which QPU ran the job or who sealed it. Capsules are tamper-evident, not authenticated, and an ID is only as trustworthy as the channel you got it through.

Lifecycle

  1. draftBeing assembled. The manifest can change.
  2. runnableReady to execute. Requirements are locked.
  3. sealedExecution complete. Credentials scanned, digests written, immutable.
  4. archivedLong-term storage. No further changes.

From the next release, verify fails any capsule that is not sealed or archived, so a sealed manifest edited back to draft no longer passes without an ID. The Marqov platform adds a published state for capsules shared with its community. That state is a platform feature and is not in the v1 spec.

Try it in two minutes

Python 3.10 or later. No account or credentials. The counts are illustrative, so nothing executes on a backend.

python -m pip install marqov-capsule==0.2.4

marqov-capsule init ./bell --name bell-state-v1 --paradigm gate-based --qubits 2
echo '{"00": 512, "11": 488}' > bell/results.json

marqov-capsule seal ./bell                  # prints the capsule ID
marqov-capsule pack ./bell -o bell.capsule
marqov-capsule verify bell.capsule --id <capsule-id>

# Now change one byte and verify the directory
echo x >> bell/results.json
marqov-capsule verify ./bell                # Integrity verification: FAIL

Your ID will differ from the one on this page because the manifest records seal timestamps. A real capsule also lists its task executions and backend. Run seal --dry-run first to catch misspelled manifest keys before they are sealed in. The README covers the Python builder API.

Where it fits

The SDK produces results. The capsule package turns them into a record. The platform runs that same package in its worker, stores the files, and can start new jobs from a capsule. The .capsule file can leave the platform, and anyone can check it with the open-source CLI.

What exists today

CapabilityStatusDetail
Content ID and digest chainShipsSpecified in v1 with conformance fixtures.
CompressionShipsDeterministic gzipped tar. Packing twice gives identical bytes.
Credential scanShipsRuns before sealing and refuses known credential shapes. Detection is best-effort.
Hardened readingShipsExtraction rejects duplicate or colliding names, ambiguous layouts, and links or special files.
Result comparisonShipscompare tests two count samples and returns VERIFIED or INCONCLUSIVE. Small samples stay INCONCLUSIVE. You choose what to compare.
Manifest typo checksPartialseal warns about keys the schema does not declare, but still seals them. Refusing them is under discussion.
RerunPartialThe platform starts a new job from its stored script. A capsule file cannot yet rerun alone, and results are not compared automatically.
Environment capturePartialAuthors supply environment files. Sealing does not inspect or lock the host.
Seeds and exact replayPilotA macOS pilot in the repository replays a seeded Bell run in two fresh offline environments and checks it against an independent calculation. The format itself has no seed field yet.
SignaturesNot builtOn the roadmap. This is what would answer who sealed a capsule.
EncryptionNot builtNo design yet. Capsules are readable by anyone who holds them.
