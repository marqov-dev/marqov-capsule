## Current bundled checkpoint

The sections below preserve the earlier audit and its successive follow-ups.
This checkpoint adds local work after the legacy-verifier change; it has not
been pushed or submitted as another PR.

- Schema validation now enforces UUIDs and the canonical JSON data model,
  rejecting typed keys, normalization collisions, nonfinite numbers, oversized
  integers, binary values, and cyclic aliases. Invalid UTF-8 is a validation
  failure. Shared acyclic values remain supported.
- Checksum verification resolves decomposed Unicode filenames and rejects
  ambiguous normalized names. Sealing rejects encoded-path collisions.
  Verification refuses symlinked metadata and listed nonregular payloads,
  including FIFOs, before reading their contents.
- CLI regressions reject deleted payloads and a rewritten digest chain when
  checked against the original trusted ID. Internal consistency alone does
  not authenticate that ID.
- The spec now states the existing choices explicitly: classical zero-qubit
  workloads are valid, this schema pins manifest version `1.0.0`, and environment
  capture is supplied by the author. Canonical helper typed-key coercion remains
  a legacy extension; schema validation rejects those keys.

## Conference claim and next boundary

The demonstrated claim is: “This archive preserves the files from an SDK
experiment, and a recipient can verify that they match a trusted capsule ID.”
It does not establish QPU provenance, signer identity, scientific correctness,
or statistical replication. A fresh seal includes new timestamps and can have
a different ID; deterministic packing applies to the same sealed directory.

Next review the local change, finish the release-gate dispositions above, and
run the release workflow's preflight. The platform integration needs its own
reviewable change and end-to-end proof before it joins the conference release.

## Independent conformance follow-up after #75 merged

PR #75 merged as `caaedab`. A pinned Node/YAML checker now reads the original
six fixture manifests and payload files with an independent parser, serializer,
path encoder, and hash implementation. It also checks nine canonicalization
cases and three checksum-path cases: 18 vectors total, with a required CI job.
It does not claim schema validation, credential scanning, statistics, or archive
extraction as a second implementation. Full independent interoperability and
external review remain open.

The new path vectors exposed two actual reader defects: percent-encoded paths
were looked up literally, and a single checksum line with a colon-space filename
could be misread as YAML. The verifier now recognizes normative checksum lines,
decodes the four permitted escapes once, preserves trailing filename spaces,
and rejects noncanonical escapes and duplicate line paths. Legacy YAML mappings
retain literal filename semantics. Existing valid fixture IDs are unchanged.
A sealed archive round-trip covers encoded filenames and trusted-ID verification.

Validation for this follow-up: 339 full-suite tests pass; the NumPy-free suite
runs 314 tests with 25 skips; the independent Node checker passes all 18 vectors.
The JavaScript dependency is confined to development tooling and adds no Python
runtime dependencies. Public repository visibility remains unchanged.
