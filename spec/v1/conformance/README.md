# Conformance vectors

`golden/expected.json` publishes expected results for all six existing capsule
manifests. Paths are relative to this directory. The golden files live outside
capsule directories so they do not change the sealed payload set or its ID.

Each row records:

- `canonical_file`: exact canonical JSON bytes, UTF-8 with no trailing newline.
- `capsule_id`: `mqc:1:` plus SHA-256 of those bytes.
- `checksums_digest`: `sha256:` plus SHA-256 of the fixture's `.checksums`, or
  null for a fixture with no checksum file. Null makes no integrity claim.
- `schema_valid` and `schema_error_paths`: schema verdict and reference-validator
  slash-separated error locations, sorted. Error prose is not normative.
- `has_secrets` and `secret_locations`: expected reference-scanner findings by
  relative filename and one-based line number. Credentials are synthetic.

A computable ID does not imply schema validity or successful sealing. The
invalid and credential-bearing fixtures deliberately separate those properties.
The derived child pins its parent's published ID and exercises the empty-payload
checksum file (zero bytes).

`golden/canonical-edge-cases.json` supplies YAML fragments and exact expected
canonical UTF-8 strings, or an explicit rejection expectation. These fragments
exercise the canonicalization layer, not complete schema-valid capsules:
JSON-aligned YAML typing, timestamps, nulls, NFC, UTF-16 key sorting, JCS number
formatting, duplicate and normalized-colliding keys, unsafe
integers, and explicitly typed non-finite values. An untagged `.nan` is a
literal string under the JSON-aligned loader.

Run `python -m pytest tests/test_conformance_vectors.py -q` from the repo root.
Tests compare the implementation to fixed checked-in values; they never update
goldens. The digest-chain check independently hashes payloads, parses checksum
lines, checks the closed file set, and serializes the ordinary fixture JSON
using the Python standard library. The edge-case canonical strings were written
explicitly from the format rules, not generated by the implementation.

The standard-library serializer covers only the ordinary fixtures' key and
number subset. The independent Node checker below adds YAML parsing, Unicode,
number formatting, and path vectors; external review remains release work.
Changes to expected bytes require an explanation of their identity impact;
do not regenerate goldens just to make a failing test pass.

The current Python API also accepts typed mapping keys and converts them to
strings for compatibility. That permissive behavior is not certified by these
vectors: spec §5 requires string keys. Normalization collisions are rejected,
including collisions between a typed key and its string spelling.

## Independent Node checker

From the repository root, with Node 22 and npm:

```bash
npm ci --prefix tools/conformance --ignore-scripts
npm test --prefix tools/conformance
```

This checker uses a pinned independent YAML parser and its own canonical JSON
serializer, path encoder, SHA-256 hashing, and corpus walk. It reads the original
YAML and payload files, not Python-produced intermediate objects. It matches all
six manifest IDs and checksum bytes, nine canonicalization cases, and three path
vectors. The required `conformance-node` CI job runs it independently of Python.

`golden/checksum-path-cases.json` publishes exact checksum bytes for an empty
payload and filenames containing whitespace (including a trailing space), a
literal percent escape, CR/LF, backslash, decomposed Unicode, and characters whose
UTF-8 byte order differs from UTF-16 order. Expected bytes were computed with
standard-library hashing and explicit format rules, without the capsule writer.
The Python tests materialize NFC filenames on POSIX, test writer and reader
against these values, and exercise a sealed archive round-trip. Windows cannot
represent all of these filenames and is not covered by the filesystem tests.

The Node tool is a corpus checker, not a production reader or a complete second
implementation. It does not validate the JSON Schema, run credential detection,
implement statistical verification, or extract archives. It rejects aliases and
non-string keys, whereas the Python API has some legacy permissive behavior.
External review and broader interoperability testing remain release work.

A single-file colon-space case also ensures a valid checksum line is not
misclassified as a legacy YAML mapping.
